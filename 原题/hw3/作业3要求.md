## 四、任务 1:rasterize_triangle 要做的 5 件事

框架在 L262-281 留了注释,拆开就是:

1. **包围盒**:取三顶点屏幕坐标 x/y 的 min/max,**必须 clamp 到 `[0, width-1]` / `[0, height-1]`**。用 `std::floor`/`std::ceil` 再转 int。
2. **遍历**:对 bbox 内每个像素,采样点取**像素中心** `(x + 0.5, y + 0.5)`。
3. **重心坐标**:`computeBarycentric2D(x + 0.5, y + 0.5, t.v)` 得到 `(alpha, beta, gamma)`,判 `alpha/beta/gamma` 是否都 ≥ 0(等价于 insideTriangle;用哪个都行,二选一别混用)。
4. **深度插值 + Z-Buffer**:框架 L268-270 已经**把代码注释给你了**(透视校正的正确写法):
   ```
   float Z  = 1.0 / (alpha / v[0].w() + beta / v[1].w() + gamma / v[2].w());
   float zp = alpha * v[0].z() / v[0].w() + beta * v[1].z() / v[1].w() + gamma * v[2].z() / v[2].w();
   zp *= Z;
   ```
   ⚠️ **和 HW2 的关键区别:本次 `depth_buf` 初值是 `+infinity`**(`clear()` 里 `std::numeric_limits<float>::infinity()`),而视口变换 `vert.z() = vert.z() * f1 + f2` 把 NDC z ∈ [-1,1] 映射到 `[0.1, 50]`,**z 越大越远**。
   → 所以判断是 **`if (zp < depth_buf[index])`**(HW2 是 `if (z < depth_buf)` 靠 -inf 初值,方向反了会全错)。
5. **插值属性 + 调 shader**(框架 L272-281):
   ```cpp
   auto interpolated_color      = interpolate(alpha, beta, gamma, t.color[0], t.color[1], t.color[2], 1);
   auto interpolated_normal     = interpolate(alpha, beta, gamma, t.normal[0], t.normal[1], t.normal[2], 1);
   auto interpolated_texcoords  = interpolate(alpha, beta, gamma, t.tex_coords[0], t.tex_coords[1], t.tex_coords[2], 1);
   auto interpolated_shadingcoords = interpolate(alpha, beta, gamma, view_pos[0], view_pos[1], view_pos[2], 1);

   fragment_shader_payload payload(interpolated_color, interpolated_normal.normalized(),
                                   interpolated_texcoords, texture ? &*texture : nullptr);
   payload.view_pos = interpolated_shadingcoords;
   auto pixel_color = fragment_shader(payload);
   ```
   然后写 `frame_buf`(用 `get_index(x, y)`)和 `depth_buf`。
   ⚠️ `weight` 参数**传 1**。框架的 `interpolate` 实现是 `(α·v1 + β·v2 + γ·v3) / weight`（`rasterizer.cpp` L243-246），只有**统一除法**这一种能力 —— 传 `Z` 会让属性整体乘上一个标量（颜色变亮变暗、uv 被拉伸），是错的。想要**真正的透视校正**必须手动展开成 `(α·A/w0 + β·B/w1 + γ·C/w2) * Z`（`w_i` 用 `t.v[i].w()`，见下方框架疑点），属于可选进阶。

**验证点**:跑 `./Rasterizer output.png normal`,能看到 spot 奶牛的法线颜色图(蓝紫为主、有立体感)。**这一步过了再往下做。**

## 五、任务 3-6:四个 shader 的公式

### 通用:Blinn-Phong(任务 3)

对每个光源累加三项:

```
L = La + Ld + Ls

La = ka * Ia                                    ← 注意没有 max,直接乘
Ld = kd * (I / r²) * max(0, n · l)              ← r 是光源到着色点的距离
Ls = ks * (I / r²) * max(0, n · h)^p            ← h = normalize(l + v)
```

- `n` = 插值后归一化的法线;`l` = 着色点指向光源的方向(**归一化**);`v` = 着色点指向眼睛 `eye_pos` 的方向(**归一化**)
- `r²` = `(light.position - point).squaredNorm()` —— **I 要除以 r²**,漏了就全白
- `point` = `payload.view_pos`(view space 的着色点位置),**不是**屏幕坐标
- `h = (l + v).normalized()` —— half vector
- 累加完 **× 255** 返回(框架最后一行已经写了 `return result_color * 255.f`,你只管累加 0-1 的结果)

**验证点**:`./Rasterizer output.png phong`,奶牛有明暗过渡 + 两个明显高光斑。

### 任务 4:texture —— 在 phong 基础上换 kd

- 采样:`payload.texture->getColor(payload.tex_coords.x(), payload.tex_coords.y())` → 返回 0-255 的 `Vector3f`
- `kd = texture_color / 255.f`(框架 L95 已经写好了)
- 其余和 phong 一模一样

**验证点**:`./Rasterizer output.png texture`,贴图**不能扭曲**(扭曲 = 透视校正插值写错了)。

### 任务 5:bump —— 改法线,不改位置

框架 L224-232 已经把**伪代码**给你了,照做:

```
h(u,v): 取纹理 (u,v) 处的颜色,返回它的 .norm()   ← 助教明确规定用 norm,不要自己换别的
n = normal = (x, y, z)
t = (x*y/sqrt(x*x+z*z), sqrt(x*x+z*z), z*y/sqrt(x*x+z*z))
b = n cross t
TBN = [t b n]
dU = kh * kn * (h(u+1/w, v) - h(u,v))
dV = kh * kn * (h(u, v+1/h) - h(u,v))
ln = (-dU, -dV, 1)
n = normalize(TBN * ln)
```

- `w`,`h` 是**纹理的宽度与高度**(`payload.texture->width` / `->height`)
- ⚠️ **整数除法陷阱**:必须写 `h(u + 1.0f/w, v)`,写成 `1/w` 会得到 0
- ⚠️ 改完的 normal **仍需 normalize**(助教第 4 条)
- **不改 `point`** —— 这是 bump 和 displacement 的唯一区别
- 最后 `result_color = normal;`(框架 L236 已经写了,即直接输出法线可视化)

**验证点**:`./Rasterizer output.png bump`,表面有凹凸颗粒感,但**物体轮廓仍然是光滑的**。

### 任务 6:displacement —— 真的改位置

和 bump **完全一样**,只多两处、改一处:

- 多算 `h(u,v)`(bump 里只算了差值,没直接用值)
- **改位置**:`point = point + kn * n * h(u,v)`(注释 L183)—— 用**原始**的 n
- 然后**照常走一遍 Blinn-Phong**(注释 L189-195),而不是 `result_color = normal`

**验证点**:`./Rasterizer output.png displacement`,凹凸感与明暗起伏比 bump 更强。⚠️ **轮廓不会变** —— 位移发生在 fragment shader 内部(只改着色用的着色点位置),而像素覆盖范围早在光栅化阶段就定型了。实测:displacement 图的非黑像素数与包围盒跟 phong **完全一致**(60768 个 / x[211,502] y[132,510])。(2026-09-25 订正:原稿写"轮廓也起伏",在本框架下不成立。)

## 六、助教《作业三常见问题集合》8 条(官方论坛帖,动手前必读)

1. bump mapping 部分的 `h(u,v) = texture_color(u,v).norm`,`u,v` 是 `tex_coords`,`w,h` 是纹理的宽高
2. `rasterizer.cpp` 中 `v = t.toVector4()`
3. `get_projection_matrix` 里的 `eye_fov` 要转成**弧度制**
4. bump 与 displacement 中修改后的 normal **仍需 normalize**
5. 可能用到的 Eigen 方法:`norm()`、`normalized()`、`cwiseProduct()`
6. 实现 `h(u+1/w, v)` 时必须写成 `h(u+1.0/w, v)` —— **整数除法陷阱**
7. 凹凸纹理正规做法是单通道灰度图;本课程为框架简便用了一张 RGB 图当凹凸贴图,需要指定规则把彩色投影到灰度 —— 助教「恰好」选了 `norm`,为保证结果一致,**统一用 norm**
