## 与原版框架的差异（共 2 处）

1. **`Texture.hpp` 的 `getColor()` 补了纹理坐标边界检查**
   （框架原版没有，2026-09-25 补的）

   `spot_triangulated_good.obj` 的 3225 个纹理坐标里 **u 最小到 -0.052242**
   （u ∈ [-0.052, 0.989]、v ∈ [0.111, 1.00065]），原版 `u_img = u * width` 会算出**负的列索引**
   （-0.052 × 1024 ≈ -53）。`cv::Mat::at` 在 **Debug 下直接断言崩溃**：

   ```
   Assertion failed ((unsigned)(i1 * DataType<_Tp>::channels) < (unsigned)(size.p[1] * channels()))
   in cv::Mat::at, mat.inl.hpp
   ```

   Release 下不崩，但那是越界读（未定义行为）。
   修复方式：uv 先夹到 `[0,1]`，索引改用 `(width-1)` / `(height-1)`，保证落在 `[0, size-1]`。
   实测影响面：修复前后同一张 `texture` 图有 **0.668%**（约 3274 个像素）不同。

2. **`CMakeLists.txt` 是移植到 Windows / MSVC 的版本**，官方原文件保留为 `CMakeLists.txt.linux-original`。

## 编译运行

依赖 **Eigen**（纯头文件）+ **OpenCV**，路径写在 `CMakeLists.txt` 顶部，换机器需要改。

```powershell
cmake -S . -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Release
```

```powershell
cd build
.\Rasterizer.exe output_normal.png       normal
.\Rasterizer.exe output_phong.png        phong
.\Rasterizer.exe output_texture.png      texture
.\Rasterizer.exe output_bump.png         bump
.\Rasterizer.exe output_displacement.png displacement
```

- ⚠️ 参数顺序是 **`<输出图片> <shader名>`**；参数个数不对（比如只给一个）会掉进 `cv::imshow` 交互模式，
  在命令行下表现为卡住不退出。
- ⚠️ `models/spot/` 走的是相对路径 `../models/spot/...`，所以**工作目录必须是 `build/`**，不能在别处运行 exe。
